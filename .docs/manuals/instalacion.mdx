## 1. Introducción

Este manual proporciona instrucciones detalladas para la instalación, configuración y puesta en marcha de BioPlatform Caldas en diferentes entornos. Está dirigido a administradores de sistemas, DevOps y personal de infraestructura.

### 1.1 Alcance

Cubre la instalación completa de:
- Infraestructura de bases de datos (SQL Server, PostgreSQL, Redis, ChromaDB, MongoDB)
- Backend .NET 8 (API principal)
- Servicio de IA (Python/FastAPI)
- Frontend Web (Next.js 14)
- Frontend Mobile (React Native/Expo)

## 3. Preparación del Entorno

### 3.1 Instalar Docker

#### Windows (Windows Server 2025 / Windows 11)
1. Descargar Docker Desktop desde [docker.com/products/docker-desktop](https://www.docker.com/products/docker-desktop)
2. Ejecutar el instalador y seleccionar **"Use WSL 2 instead of Hyper-V"**
3. Una vez instalado, habilitar la integración con WSL2:
   ```powershell
   # En PowerShell como Administrador
   wsl --install -d ubuntu
   docker info  # Verificar que Docker esté funcionando
   ```
4. Configurar Docker para iniciar con Windows:
   - Abrir Docker Desktop → Settings → General → **"Start Docker Desktop when you log in"**
   - Recursos: Settings → Resources → Advanced → Asignar mínimo 4 GB RAM y 2 CPUs

#### Linux (Ubuntu/Debian)
```bash
# Actualizar paquetes
sudo apt update && sudo apt upgrade -y

# Instalar dependencias
sudo apt install -y ca-certificates curl gnupg lsb-release

# Agregar repositorio oficial de Docker
sudo mkdir -p /etc/apt/keyrings
curl -fsSL https://download.docker.com/linux/ubuntu/gpg | sudo gpg --dearmor -o /etc/apt/keyrings/docker.gpg
echo "deb [arch=$(dpkg --print-architecture) signed-by=/etc/apt/keyrings/docker.gpg] https://download.docker.com/linux/ubuntu $(lsb_release -cs) stable" | sudo tee /etc/apt/sources.list.d/docker.list > /dev/null

# Instalar Docker Engine
sudo apt update
sudo apt install -y docker-ce docker-ce-cli containerd.io docker-compose-plugin

# Agregar usuario al grupo docker (evitar sudo)
sudo usermod -aG docker $USER
newgrp docker  # Recargar grupo

# Verificar instalación
docker --version
docker compose version

# Configurar Docker para iniciar con el sistema
sudo systemctl enable docker
sudo systemctl start docker
```

## 6. Configuración de Docker Compose

### 6.1 Archivos de Configuración

El proyecto incluye dos archivos de Docker Compose:

| Archivo | Propósito |
|---------|-----------|
| `docker-compose.yml` | Infraestructura base (BD, caché, vector store) |
| `docker-compose.override.yml` | Configuraciones específicas de desarrollo |

### 6.2 Personalización de Servicios

#### Modificar Puertos (Ejemplo: PostgreSQL)
```yaml
# En docker-compose.override.yml
services:
  postgres:
    ports:
      - "5434:5432"  # Cambiar puerto local a 5434
```

#### Agregar Límites de Recursos
```yaml
services:
  sqlserver:
    deploy:
      resources:
        limits:
          cpus: '2'
          memory: 4G
```

#### Configurar Red y Volúmenes
```yaml
services:
  postgres:
    volumes:
      - postgres_data:/var/lib/postgresql/data
    networks:
      - bioplatform-network
```

### 6.3 Comandos Útiles de Docker Compose

```bash
# Construir y levantar servicios
docker compose up -d --build

# Ver estado de servicios
docker compose ps

# Ver logs en tiempo real
docker compose logs -f

# Ver logs de un servicio específico
docker compose logs -f postgres

# Reiniciar un servicio
docker compose restart sqlserver

# Detener servicios (sin eliminar volúmenes)
docker compose down

# Detener servicios y eliminar volúmenes (pérdida de datos)
docker compose down -v

# Ejecutar comando dentro de un contenedor
docker compose exec postgres psql -U postgres -d BioCommerce_Scientific

# Ver uso de recursos
docker compose stats
```

### 6.4 Gestión de Volúmenes

```bash
# Listar volúmenes
docker volume ls

# Inspeccionar un volumen
docker volume inspect bioplatform_postgres_data

# Respaldar un volumen
docker run --rm -v bioplatform_postgres_data:/source -v $(pwd):/backup alpine tar czf /backup/postgres_backup.tar.gz -C /source .

# Restaurar un volumen
docker run --rm -v bioplatform_postgres_data:/destination -v $(pwd):/backup alpine tar xzf /backup/postgres_backup.tar.gz -C /destination
```

## 7. Configuración de SSL/TLS

### 7.1 Certificados para Desarrollo (Self-Signed)

```bash
# Generar certificado autofirmado para desarrollo
openssl req -x509 -nodes -days 365 -newkey rsa:2048 \
  -keyout docker/nginx/ssl/bioplatform.key \
  -out docker/nginx/ssl/bioplatform.crt \
  -subj "/C=CO/ST=Caldas/L=Manizales/O=BioPlatform/CN=localhost"
```

### 7.2 Certificados para Producción (Let's Encrypt)

```bash
# Instalar Certbot en Ubuntu/Debian
sudo apt install -y certbot python3-certbot-nginx

# Obtener certificado
sudo certbot --nginx -d bioplatformcaldas.co -d api.bioplatformcaldas.co

# Renovación automática (Certbot agrega cron automáticamente)
sudo certbot renew --dry-run
```

### 7.3 Configuración de NGINX con SSL

```nginx
# docker/nginx/conf.d/default.conf
server {
    listen 80;
    server_name bioplatformcaldas.co;
    return 301 https://$server_name$request_uri;
}

server {
    listen 443 ssl http2;
    server_name bioplatformcaldas.co;

    ssl_certificate /etc/nginx/ssl/bioplatform.crt;
    ssl_certificate_key /etc/nginx/ssl/bioplatform.key;
    ssl_protocols TLSv1.2 TLSv1.3;
    ssl_ciphers HIGH:!aNULL:!MD5;

    location / {
        proxy_pass http://frontend:3000;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
    }

    location /api/ {
        proxy_pass http://backend:5070;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
    }

    location /ai/ {
        proxy_pass http://ai-service:8000;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
    }
}
```

#### Servidor SMTP Corporativo
```
SMTP_HOST=smtp.correo-empresa.co

SMTP_PASSWORD=contraseña
```

**Verificación:**
- Usar el endpoint `POST /api/auth/test-email` en Swagger
- O verificar en logs que no hay errores SMTP al registrar un usuario

### 9.2 Almacenamiento de Imágenes (Azure Blob Storage)

1. Crear cuenta de almacenamiento en [Azure Portal](https://portal.azure.com)
2. Crear contenedores:
   - `species-images` (para fotos de especies)
   - `product-images` (para imágenes del marketplace)
3. Obtener cadena de conexión: **Configuración → Claves de acceso**
4. Configurar en `.env`:
```
AZURE_STORAGE_CONNECTION_STRING=DefaultEndpointsProtocol=https;AccountName=<nombre>;AccountKey=<clave>;EndpointSuffix=core.windows.net
AZURE_STORAGE_CONTAINER_SPECIES=species-images
AZURE_STORAGE_CONTAINER_PRODUCTS=product-images
```

**Alternativa: AWS S3**
```
AWS_ACCESS_KEY_ID=<tu-access-key>
AWS_SECRET_ACCESS_KEY=<tu-secret-key>
AWS_REGION=us-east-1
S3_BUCKET_NAME=bioplatform-images
```

### 9.3 OpenAI API

1. Crear cuenta en [OpenAI Platform](https://platform.openai.com)
2. Agregar créditos (mínimo $5 USD)
3. Generar API Key en **API Keys**
4. Configurar en `.env`:
```
OPENAI_API_KEY=sk-proj-<tu-api-key>
OPENAI_MODEL=gpt-4-turbo-preview
OPENAI_EMBEDDING_MODEL=text-embedding-3-small
```

**Verificación:**
```bash
curl -X POST http://localhost:8000/api/rag/test \
  -H "Content-Type: application/json" \
  -d '{"query": "¿Qué es la taxonomía?"}'
```

### 9.4 Stripe (Pasarela de Pagos)

1. Crear cuenta en [Stripe Dashboard](https://dashboard.stripe.com)
2. Obtener claves de prueba (sandbox): **Developers → API Keys**
3. Configurar webhook: **Developers → Webhooks → Add endpoint**
   - URL: `https://api.bioplatformcaldas.co/api/payments/webhook`
   - Eventos: `checkout.session.completed`, `payment_intent.succeeded`
4. Configurar en `.env`:

### 10.2 Configuración de Seguridad

```nginx
# docker/nginx/conf.d/security.conf
# Headers de seguridad
add_header X-Frame-Options "SAMEORIGIN" always;
add_header X-Content-Type-Options "nosniff" always;
add_header X-XSS-Protection "1; mode=block" always;
add_header Strict-Transport-Security "max-age=31536000; includeSubDomains" always;
add_header Content-Security-Policy "default-src 'self'; script-src 'self' 'unsafe-inline'; style-src 'self' 'unsafe-inline'; img-src 'self' data: https:; font-src 'self' data:; connect-src 'self' https:;";

# Limitar métodos HTTP
if ($request_method !~ ^(GET|POST|PUT|DELETE|PATCH|OPTIONS)$) {
    return 405;
}

# Limitar tamaño de body
client_max_body_size 20M;
```

## 12. Solución de Problemas de Instalación

### 12.1 Docker no inicia

| Síntoma | Causa | Solución |
|---------|-------|----------|
| `Cannot connect to the Docker daemon` | Docker no está corriendo | Iniciar Docker Desktop o `sudo systemctl start docker` |
| `Access denied` en Linux | Usuario no está en grupo docker | `sudo usermod -aG docker $USER && newgrp docker` |
| `WSL 2 installation is incomplete` (Windows) | WSL2 no instalado | `wsl --install -d ubuntu` desde PowerShell Admin |
| Puerto ya en uso | Otro servicio ocupa el puerto | Cambiar puerto en `docker-compose.yml` o detener el otro servicio |

### 12.2 Contenedores no se inician
