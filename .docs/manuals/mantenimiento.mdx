## 1. Introducción

Este manual describe los procedimientos de mantenimiento necesarios para garantizar la operación continua, segura y eficiente de BioPlatform Caldas en entornos de producción y staging. Está dirigido a administradores de sistemas, personal de operaciones (DevOps) y desarrolladores con responsabilidades de mantenimiento.

### 1.1 Responsabilidades

| Rol | Responsabilidades de Mantenimiento |
|-----|-----------------------------------|
| Administrador de Sistemas | Infraestructura, backups, monitoreo, SSL/TLS |
| DevOps | CI/CD, actualizaciones, despliegues, rollbacks |
| Desarrollador .NET | Migraciones, parches del backend |
| Desarrollador Python | Mantenimiento del AI Service, modelos |
| Desarrollador Frontend | Actualizaciones de dependencias web/mobile |
| DBA (Administrador BD) | Optimización de consultas, limpieza, integridad |

### 1.2 Programación de Mantenimiento

| Tipo | Frecuencia | Ventana de Tiempo | Notificar |
|------|------------|-------------------|-----------|
| Preventivo | Mensual | Domingo 02:00–06:00 | 7 días antes |
| Actualizaciones | Según necesidad | Fuera de horas hábiles | 3 días antes |
| Backups | Diario (automático) | 03:00 – 04:00 | No requiere |
| Rotación de secretos | Trimestral | Programada | 7 días antes |
| Limpieza de datos | Semanal | Automatizado | No requiere |
| Monitoreo de logs | Continuo | Tiempo real | No requiere |

## 3. Backup y Restauración de Datos

### 3.1 Estrategia de Backup

| Dato | Método | Frecuencia | Retención |
|------|--------|------------|-----------|
| SQL Server (transaccional) | Backup completo diario + logs cada hora | Diario | 30 días |
| PostgreSQL (científica) | pg_dump diario + WAL continuo | Diario | 30 días |
| ChromaDB (vectores) | Snapshot + export JSON | Semanal | 90 días |
| Redis (caché) | Backup RDB + AOF | Diario | 7 días |
| MongoDB (logs) | mongodump | Semanal | 90 días |
| Imágenes (Blob/S3) | Replicación del proveedor | Continua | N/A |
| Archivos .env | Backup cifrado (copia manual) | Por cambio | Indefinido |
| Configuración Docker | docker-compose.yml + volúmenes | Por cambio | Indefinido |

### 3.2 Backup Automatizado con Scripts

#### Backup Completo (Script Centralizado)

Crear `/usr/local/bin/bioplatform-backup.sh`:

```bash
#!/bin/bash
# ===========================================
# BioPlatform Caldas - Backup Automatizado
# ===========================================
BACKUP_DIR="/backup/bioplatform"
DATE=$(date +%Y%m%d_%H%M%S)
RETENTION_DAYS=30

mkdir -p "$BACKUP_DIR/sqlserver" "$BACKUP_DIR/postgres" "$BACKUP_DIR/chromadb"

# SQL Server
docker exec bioplatform-sqlserver /opt/mssql-tools18/bin/sqlcmd \
  -S localhost -U SA -P "$DB_SQL_PASSWORD" -C \
  -Q "BACKUP DATABASE [BioCommerce_Transactional] TO DISK = '/var/opt/mssql/data/backup_$DATE.bak' WITH COMPRESSION"

docker cp bioplatform-sqlserver:/var/opt/mssql/data/backup_$DATE.bak "$BACKUP_DIR/sqlserver/"

# PostgreSQL
docker exec bioplatform-postgres pg_dump -U postgres \
  -d BioCommerce_Scientific -F c \
  > "$BACKUP_DIR/postgres/scientific_$DATE.dump"

# MongoDB (si está habilitado)
docker exec bioplatform-mongodb mongodump \
  --username "$MONGO_USER" --password "$MONGO_PASSWORD" \
  --authenticationDatabase admin \
  --db BioCommerce_Logs \
  --archive > "$BACKUP_DIR/mongodb/logs_$DATE.archive"

# Limpiar backups antiguos
find "$BACKUP_DIR/sqlserver" -type f -mtime +$RETENTION_DAYS -delete
find "$BACKUP_DIR/postgres" -type f -mtime +$RETENTION_DAYS -delete
find "$BACKUP_DIR/chromadb" -type f -mtime +90 -delete
find "$BACKUP_DIR/mongodb" -type f -mtime +90 -delete

# Verificar integridad
echo "Backup completado: $DATE" >> "$BACKUP_DIR/backup.log"
```

Programar en cron:
```bash
# Ejecutar diario a las 3:00 AM
0 3 * * * /usr/local/bin/bioplatform-backup.sh
```

### 3.4 Restauración de Datos

#### Restaurar SQL Server
```bash
# 1. Copiar backup al contenedor
docker cp backup_20260601_030000.bak bioplatform-sqlserver:/var/opt/mssql/data/

# 2. Restaurar base de datos
docker exec bioplatform-sqlserver /opt/mssql-tools18/bin/sqlcmd \
  -S localhost -U SA -P "$DB_SQL_PASSWORD" -C \
  -Q "RESTORE DATABASE [BioCommerce_Transactional] FROM DISK = '/var/opt/mssql/data/backup_20260601_030000.bak' WITH REPLACE"

# 3. Verificar integridad
docker exec bioplatform-sqlserver /opt/mssql-tools18/bin/sqlcmd \
  -S localhost -U SA -P "$DB_SQL_PASSWORD" -C \
  -Q "DBCC CHECKDB('BioCommerce_Transactional')"
```

#### Restaurar PostgreSQL
```bash
# 1. Eliminar base de datos existente (si aplica)
docker exec bioplatform-postgres psql -U postgres \
  -c "DROP DATABASE IF EXISTS BioCommerce_Scientific"

# 2. Crear base de datos vacía
docker exec bioplatform-postgres psql -U postgres \
  -c "CREATE DATABASE BioCommerce_Scientific"

# 3. Restaurar desde dump
cat scientific_20260601.dump | docker exec -i bioplatform-postgres \
  pg_restore -U postgres -d BioCommerce_Scientific --no-owner

# 4. Verificar integridad
docker exec bioplatform-postgres psql -U postgres -d BioCommerce_Scientific \
  -c "SELECT count(*) FROM information_schema.tables WHERE table_schema = 'public'"
```

#### Restaurar Volúmenes Docker
```bash
# Restaurar volumen de PostgreSQL
docker run --rm -v bioplatform_postgres_data:/destination \
  -v /backup/bioplatform/volumes:/source \
  alpine tar xzf /source/postgres_data_20260601.tar.gz -C /destination

# Luego reiniciar el contenedor
docker compose up -d postgres
```

```bash
  fi
done
```

### 4.5 Seq: Gestión de Logs Centralizados

Seq está disponible en http://localhost:5341 y recibe logs estructurados de:

- **Backend .NET**: Envía logs mediante **Serilog** con niveles: Verbose, Debug, Information, Warning, Error, Fatal
- **AI Service (Python)**: Envía logs mediante **structlog** con formato JSON

**Consultas útiles en Seq:**

```
# Errores de las últimas 24 horas
@Level = "Error" and @Timestamp > now - 1d

# Errores de autenticación fallida
@Message like "Failed login*" or @Message like "Invalid token*"

# Rendimiento de APIs lentas
@Duration > 5000 and @Level = "Warning"

# Agrupar errores por servicio
select @Module, count(*) as Count group by @Module
```

## 7. Rotación de Secretos y Certificados

### 7.1 Calendario de Rotación

| Secreto | Frecuencia | Método |
|---------|------------|--------|
| JWT Secret | Trimestral | Generar nuevo con `openssl rand -base64 32` |
| Contraseñas BD | Trimestral | Cambiar en .env y en Docker |
| API Keys (OpenAI, Stripe) | Anual | Regenerar desde panel del proveedor |
| Certificados SSL | Anual (o antes si expiran) | Certbot renew |
| Contraseña SMTP | Trimestral | Generar nueva contraseña de aplicación |

### 7.2 Rotación de JWT Secret

```bash
# 1. Generar nuevo secret
NEW_SECRET=$(openssl rand -base64 32)
echo "Nuevo JWT_SECRET: $NEW_SECRET"

# 2. Actualizar en .env
sed -i "s/^JWT_SECRET=.*/JWT_SECRET=$NEW_SECRET/" .env

# 3. Notificar a usuarios que deben volver a iniciar sesión
# (todos los tokens actuales quedarán inválidos)

# 4. Reiniciar backend
docker compose restart backend

# 5. Verificar que el backend usa el nuevo secret
curl -X POST http://localhost:5070/api/auth/login \
  -H "Content-Type: application/json" \
  -d '{"email": "admin@bioplatform.co", "password": "..."}'
```

### 7.3 Rotación de Certificados SSL

```bash
# Renovación automática con Let's Encrypt
sudo certbot renew

# Renovación manual
sudo certbot certonly --standalone -d bioplatformcaldas.co -d api.bioplatformcaldas.co

# Copiar certificados renovados a docker/nginx/ssl/
sudo cp /etc/letsencrypt/live/bioplatformcaldas.co/fullchain.pem docker/nginx/ssl/bioplatform.crt
sudo cp /etc/letsencrypt/live/bioplatformcaldas.co/privkey.pem docker/nginx/ssl/bioplatform.key

# Recargar NGINX
docker compose exec nginx nginx -s reload

# Verificar expiración
openssl x509 -in docker/nginx/ssl/bioplatform.crt -noout -enddate
```

### 7.4 Rotación de Contraseñas de Base de Datos

```bash
# 1. Generar nueva contraseña segura
NEW_DB_PASS=$(openssl rand -base64 16)
echo "Nueva contraseña: $NEW_DB_PASS"

# 2. Cambiar contraseña en SQL Server
docker exec bioplatform-sqlserver /opt/mssql-tools18/bin/sqlcmd \
  -S localhost -U SA -P "$OLD_PASSWORD" -C \
  -Q "ALTER LOGIN SA WITH PASSWORD = '$NEW_DB_PASS'"

# 3. Cambiar contraseña en PostgreSQL
docker exec bioplatform-postgres psql -U postgres \
  -c "ALTER USER postgres WITH PASSWORD '$NEW_DB_PASS'"

# 4. Actualizar .env
DB_SQL_PASSWORD=$NEW_DB_PASS
DB_PG_PASSWORD=$NEW_DB_PASS
DB_CONNECTION_STRING_SQL=Server=localhost,1433;Database=BioCommerce_Transactional;User Id=sa;Password=$NEW_DB_PASS;TrustServerCertificate=True
DB_CONNECTION_STRING_PG=Host=localhost;Port=5433;Database=BioCommerce_Scientific;Username=postgres;Password=$NEW_DB_PASS

# 5. Reiniciar servicios que se conectan a BD
docker compose restart backend ai-service
```

## 8. Limpieza de Datos Temporales

### 8.1 Limpieza Automatizada

```bash
#!/bin/bash
# ===========================================
# BioPlatform Caldas - Limpieza de Datos Temporales
# ===========================================

# 1. Limpiar sesiones expiradas (Redis)
docker exec bioplatform-redis redis-cli EVAL "return redis.call('DEL', unpack(redis.call('KEYS', 'session:*')))" 0

# 2. Limpiar tokens de refresco expirados (SQL Server)
docker exec bioplatform-sqlserver /opt/mssql-tools18/bin/sqlcmd \
  -S localhost -U SA -P "$DB_SQL_PASSWORD" -C \
  -Q "DELETE FROM RefreshTokens WHERE ExpiresAt < DATEADD(day, -7, GETDATE())"

# 3. Limpiar logs antiguos (MongoDB - si está habilitado)
# Se maneja mediante TTL index en MongoDB

# 4. Limpiar archivos temporales del AI Service
find src/Bio.Backend.AI/data/temp -type f -mtime +7 -delete

# 5. Limpiar imágenes temporales de Docker no utilizadas
docker image prune -f

# 6. Limpiar volúmenes no utilizados
docker volume prune -f

# 7. Limpiar contenedores detenidos
docker container prune -f
```

## 9. Optimización de Base de Datos

### 9.1 SQL Server

```sql
-- Verificar fragmentación de índices
SELECT 
    OBJECT_NAME(ind.OBJECT_ID) AS TableName,
    ind.name AS IndexName,
    indexstats.avg_fragmentation_in_percent
FROM sys.dm_db_index_physical_stats(DB_ID(), NULL, NULL, NULL, NULL) indexstats
INNER JOIN sys.indexes ind ON ind.object_id = indexstats.object_id
    AND ind.index_id = indexstats.index_id
WHERE indexstats.avg_fragmentation_in_percent > 30
ORDER BY indexstats.avg_fragmentation_in_percent DESC;

-- Reconstruir índices fragmentados
ALTER INDEX ALL ON AspNetUsers REBUILD;
ALTER INDEX ALL ON Species REBUILD;
ALTER INDEX ALL ON Products REBUILD;
```

### 9.2 PostgreSQL

```sql
-- Verificar tablas que necesitan VACUUM
SELECT
    schemaname,
    relname,
    n_live_tup,
    n_dead_tup,
    round(100 * n_dead_tup / GREATEST(n_live_tup + n_dead_tup, 1), 2) AS dead_ratio
FROM pg_stat_user_tables
WHERE n_dead_tup > 1000
ORDER BY dead_ratio DESC;

-- Ejecutar VACUUM
VACUUM (VERBOSE, ANALYZE) BioCommerce_Scientific;

-- Reindexar
REINDEX DATABASE BioCommerce_Scientific;

-- Actualizar estadísticas de PostGIS
UPDATE spatial_ref_sys SET srtext = srtext;
```

### 9.3 Consultas Lentas

```bash
# SQL Server: Habilitar registro de queries lentas

  -S localhost -U SA -P "$DB_SQL_PASSWORD" -C \
```

### 9.4 Monitoreo de Conexiones Activas

```sql
-- SQL Server

    session_id, login_name, status, 
    host_name, program_name, last_request_start_time

WHERE state != 'idle';
```

```bash
# 1. Identificar última migración exitosa
dotnet ef migrations list --project Bio.Infrastructure --startup-project Bio.API

# 2. Revertir migraciones
dotnet ef database update NombreMigracionAnterior \
  --project Bio.Infrastructure --startup-project Bio.API

# 3. Verificar estado de la base de datos
dotnet ef database status --project Bio.Infrastructure --startup-project Bio.API
```

### 10.3 Rollback de Infraestructura (Docker)

```bash
# 1. Detener servicios actuales
docker compose down

# 2. Restaurar versión anterior de docker-compose.yml
git checkout HEAD~1 -- docker-compose.yml

# 3. Restaurar backups si es necesario
# (Ver sección 3.4)

# 4. Iniciar servicios con configuración anterior
docker compose up -d

# 5. Verificar
docker compose ps
```

### 10.4 Plan de Contingencia

```
1. DETENER: Detener todos los servicios no esenciales
   docker compose stop web ai mongodb

2. EVALUAR: Identificar la causa del fallo
   - Error de código → rollback de código
   - Error de datos → rollback de BD
   - Error de infraestructura → rollback de Docker

3. DECIDIR: Ejecutar el rollback correspondiente
   
4. VERIFICAR: Health check completo

5. COMUNICAR: Notificar a usuarios afectados

6. POST-MORTEM: Analizar causa raíz y documentar
```

### 10.5 Comunicación de Rollback

- **Slack/Teams**: Canal #incidencias (incluir: qué, por qué, impacto, ETA)
